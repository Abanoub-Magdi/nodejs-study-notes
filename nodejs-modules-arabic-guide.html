فهم Modules و Import / Export ببساطة

درس عربي سهل، بأمثلة عملية ورسومات واختبار سريع. الصفحة كاملة تعمل بدون إنترنت، وتقدر ترجع لها في أي وقت.

الفكرةتقسيم الملفاتالتصدير والاستيرادأكثر من ExportCacheاختبر نفسك

1. إحنا بنحل إيه؟

تخيل عامل Server وكل الكود موجود في ملف app.js: تشغيل السيرفر، فحص الـ URL، استقبال طلبات POST، وكتابة الملفات.

كل ما المشروع يكبر، الملف هيبقى أطول وأصعب في الفهم والصيانة. الحل إننا نقسم المسؤوليات على ملفات.

الخلاصة: app.js يشغّل السيرفر، و routes.js يقرر يعمل إيه مع كل Request.

2. شكل المشروع بعد التقسيم

my-project/
├── app.js
├── routes.js
└── message.txt  (created after POST)
app.jsيشغّل السيرفر
←
routes.jsيتعامل مع req و res

ملف routes.js

const fs = require('fs');

const requestHandler = (req, res) => {
  const url = req.url;
  const method = req.method;

  if (url === '/') {
    res.write('Welcome Home!');
    return res.end();
  }

  if (url === '/message' && method === 'POST') {
    fs.writeFileSync('message.txt', 'Hello!');
    res.statusCode = 302;
    res.setHeader('Location', '/');
    return res.end();
  }

  res.statusCode = 404;
  res.end('Page Not Found');
};

module.exports = requestHandler;

الـ requestHandler دالة بتستقبل req و res. جواها بنشوف المستخدم طلب أنهي URL وبأي Method.

الجزءالمعنى
reqالطلب اللي جاي من المستخدم
resرد السيرفر للمستخدم
req.urlالمسار المطلوب
req.methodنوع الطلب، مثل GET أو POST

ملف app.js

const http = require('http');
const routes = require('./routes');

const server = http.createServer(routes);
server.listen(3000);

كده app.js بقى بسيط جدًا. ولو حفظت الملفين في نفس المجلد وشغلت node app.js، السيرفر هيستقبل الطلبات على http://localhost:3000.

3. يعني إيه module.exports و require؟

اعتبر module.exports باب بتطلع منه حاجة من ملف، و require() الطريقة اللي ملف تاني بيجيب بيها الحاجة دي.

routes.jsmodule.exports = requestHandler
←
app.jsrequire('./routes')
في المثال ده، المتغير routes هيمسك نفس الدالة اللي صدّرناها باسم requestHandler.

ليه createServer(routes) من غير أقواس؟

http.createServer(routes);   // ✅ تمرير الدالة نفسها
http.createServer(routes()); // ❌ تنفيذها فورًا بدون req و res

Node.js محتاج منك مرجع للدالة علشان يناديها لما يجيله Request جديد.

ليه require('./routes') فيها ./ ؟

require('http') بيحمّل Module جاهز داخل Node.js، أما require('./routes') فبيجيب ملف محلي موجود جنب app.js. والامتداد .js اختياري هنا.

4. لو عايز تصدّر أكتر من حاجة

بدل ما تصدّر دالة واحدة، ممكن تصدّر Object فيه الدالة ونص أو أي قيم تانية.

طريقة 1: Object كامل

module.exports = {
  handler: requestHandler,
  someText: 'Welcome to Node.js'
};

طريقة 2: إضافة Properties منفصلة

module.exports.handler = requestHandler;
module.exports.someText = 'Welcome to Node.js';

طريقة 3: اختصار exports

exports.handler = requestHandler;
exports.someText = 'Welcome to Node.js';

الطرق الثلاث فوق بتوصل لنفس شكل الـ Object. وفي app.js هتستخدم:

const http = require('http');
const routes = require('./routes');

console.log(routes.someText);
const server = http.createServer(routes.handler);
server.listen(3000);
غلطة مشهورة: exports.handler = fn صح، لكن exports = fn مش بديل عن module.exports = fn. لأنك كده غيّرت المتغير المختصر فقط، مش القيمة اللي Node.js بيصدّرها.

5. إيه هو Module Cache؟

  1. أول مرة تستخدم require('./routes')، Node.js بيحمّل الملف وينفّذ محتواه.
  2. بيرجع القيمة الموجودة في module.exports.
  3. بيحتفظ بالـ Module في الـ Cache؛ فغالبًا المرات التالية مش بتنفّذ الملف من أول وجديد.
الـ Cache مش معناه إن البيانات مستحيل تتغير: لو صدّرت Object، ممكن كود تاني يعدّل Properties فيه. لكن ده مش بيعدّل نص ملف JavaScript الموجود على القرص.

6. ورقة مراجعة سريعة

الكودبيعمل إيه؟

ملحوظة: الدرس ده بيستخدم نظام CommonJS (require / module.exports). فيه كمان نظام اسمه ES Modules بيستخدم import / export.
