افهم الـ Event Loop في Node.js

صفحة مذاكرة بالعربي البسيط — مثال من الحياة، رسمة للرحلة، كود عملي، محاكاة، كروت مراجعة، واختبار. تشتغل بدون إنترنت.

1 — الفكرة في دقيقة

تخيل مطعم فيه موظف واحد بياخد الطلبات. عميل طلب أكلة هتاخد 20 دقيقة، وعميل تاني طلب مياه. لو الموظف ساب الشباك ودخل يطبخ، الكل هيستنى — ده Blocking. لكن لو بعت الطلب للمطبخ وكمل استقبال الناس — ده تقريبًا Non-Blocking.

Main JavaScript Threadالموظف اللي بينفذ JavaScript؛ مسار رئيسي واحد.
Worker Poolمساعدين لعمليات معينة زي قراءة الملفات، مش لكل العمليات.
Event Loopبينظم إمتى callbacks الجاهزة تتنفذ على الـ Main Thread.
احفظها: Node.js مش معناها إن كل حاجة بتتنفذ في نفس الوقت على الـ Main Thread. هي فعّالة لأنها بتتجنب انتظار عمليات I/O غير الضروري.

2 — رحلة قراءة ملف

لما الطلب يوصل ويحتاج يقرأ ملف، بنستخدم fs.readFile غير المتزامنة:

1. السيرفر يستقبل Request. 2. الكود يبدأ قراءة الملف. 3. عملية الملفات تتنفذ بعيدًا عن Main Thread. 4. الـ JavaScript تكمل شغلها. 5. لما القراءة تخلص، الـ callback يتنفذ على Main Thread لما ييجي دوره.

تصحيح مهم: مش كل Async Operations بتروح للـ Worker Pool. كتير من Network I/O بيتعامل معاها نظام التشغيل بآليات غير حاجزة.

3 — جرّب الفرق بين Blocking وNon-Blocking

Non-Blocking

console.log('Start');
fs.readFile('data.txt', () => {
  console.log('File Done');
});
console.log('Continue');

Blocking

console.log('Start');
fs.readFileSync('data.txt');
console.log('File Done');
console.log('Continue');
اضغط على أحد زري المحاكاة 👆

دي محاكاة تعليمية للترتيب، مش تشغيل فعلي لـ Node.js داخل المتصفح. سطور Non-Blocking بتوضح إن Continue تظهر قبل callback القراءة في المثال ده.

4 — مراحل Event Loop بطريقة سهلة

اضغط على اسم المرحلة:

Timers

تشغّل callbacks المرتبطة بـ setTimeout وsetInterval لما ميعادها يبقى مستحق. الوقت مش ضمان للتنفيذ في نفس الملّي ثانية.

Pending Callbacks

تتعامل مع callbacks معينة مؤجلة من دورات سابقة أو أحداث تخص النظام.

Poll

تستقبل أحداث I/O وتنفّذ callbacks الجاهزة، وممكن تنتظر أحداث حسب حالة البرنامج.

Check

المرحلة المرتبطة بتنفيذ callbacks المسجلة بـ setImmediate.

Close Callbacks

بتتعامل مع بعض callbacks إغلاق الموارد زي sockets.

ملحوظة متقدمة: دي صورة مبسطة. process.nextTick وPromises ليهم قواعد خاصة، والترتيب الدقيق ممكن يختلف بحسب إصدار Node.js وحالة العمليات.

5 — السيرفر ليه بيفضل شغال؟

const server = require('http').createServer((req, res) => {
  res.end('Hello');
});
server.listen(3000);

لأن server.listen بيخلي فيه Listener نشط مستني طلبات جديدة. على عكس برنامج بيعمل console.log('Hello') وبس، اللي ممكن ينتهي بعد آخر شغل نشط.

وهل بيانات الطلبات بتختلط؟

كل استدعاء للـ request callback ليه متغيراته المحلية وreq وres الخاصين بيه. لكن متغيرات Global المشتركة ممكن تعمل مشاكل لو خزّنت فيها بيانات المستخدمين غلط.

7 — اختبر فهمك

الخلاصة النهائية

Single Thread: JavaScript عادية على مسار رئيسي واحد.

Worker Pool: تنفيذ عمليات محددة بعيدة عن الـ Main Thread.

Event Loop: تنظيم callbacks الجاهزة للتنفيذ.

Blocking: شغل بيحجز الـ Main Thread ويعطل الباقي.

Non-Blocking: بدء العملية ومتابعة الشغل بدل الانتظار.

لو JavaScript نفسها فيها عملية حسابية تقيلة ومتزامنة، Node.js مش هتنقلها تلقائيًا للـ Worker Pool؛ وبالتالي ممكن تعمل Blocking.
